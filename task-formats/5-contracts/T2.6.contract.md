# Contract T2.6 — Write the routing-decision record and the generation attribution

> **Goal.** Make it impossible for a generation to exist without a record of why the provider that served it was chosen.

## Requires

- T1.1 is trusted — Create the routing-configuration and attribution migration
- T2.4 is trusted — Add the dry-run mode to the gateway

## Changes

- `libs/db/src/lib/extensions/versions.extensions.ts` — update: extend the existing `recordGeneration` input, and add the routing-decision write that every call makes, live or dry

## Ensures

What must be true when the work is done.

- **T2.6.c1** — a recorded generation carries provider, routing source and policy hash, written in the same atomic step as the asset insert and wallet decrement.
  - proof: the test tagged `[T2.6.c1]`
  - judge: runner + verifier
  - category: happy path; relates to S27
- **T2.6.c2** — a caller that supplies none of the new fields still records successfully, and the absent fields are stored as absent, not invented.
  - proof: the test tagged `[T2.6.c2]`
  - judge: runner + verifier
  - category: empty / null; relates to S43
- **T2.6.c3** — a dry-run call writes a routing-decision record carrying the attribution and the dry-run marker, performs **no** wallet decrement, and writes **no** generation-history row — it has no asset to reference.
  - proof: the test tagged `[T2.6.c3]`
  - judge: runner + verifier
  - category: boundary; relates to S58, POA-R4
- **T2.6.c4** — the routing-decision record is readable afterwards without reference to any artefact, which is what makes a dry run usable as proof of what a live request would do.
  - proof: the test tagged `[T2.6.c4]`
  - judge: runner + verifier
  - category: boundary
- **T2.6.c5** — if the attribution write fails, the whole record fails — there is no partial state in which the generation exists without it.
  - proof: the test tagged `[T2.6.c5]`
  - judge: runner + verifier
  - category: failure mode
- **T2.6.c6** — existing callers compile unchanged (the new fields are optional).
  - proof: the test tagged `[T2.6.c6]`
  - judge: runner + verifier
  - category: regression

## Preserves

What must still be true.

- **T2.6.p1** — exactly one write path for the generation half
  - proof: review of the parent's diff
  - judge: reviewer
- **T2.6.p2** — existing `recordGeneration` callers compile unchanged
  - proof: the test tagged `[T2.6.c6]`
  - judge: runner + verifier

## Forbids

- **T2.6.f1** — Must not hand-edit the generated `libs/db/src/lib/{types.ts,schemas/,repositories/}`
  - proof: review of the parent's diff
  - judge: reviewer

## Contributes to

- acceptance: S27, S43, S58 — see [acceptance.contract.md](./acceptance.contract.md)

## Rejected proofs

A verdict that accepts one of these is void.

- c3: asserting that a routing-decision row exists. Also assert there is no generation-history row and no wallet decrement.
- c5: a happy-path write. Make the attribution write fail and assert that no generation, asset or wallet change remains.

## Approach

Guidance for the builder. Not an obligation; nothing here is judged.

Extend the existing `recordGeneration` input rather than adding a second write path for the generation half — the atomicity guarantee in the `0015` migration docblock depends on there being exactly one. The routing-decision record is a separate, additional write that every call makes, live or dry (POA-R4). Regenerate the DB types after T1.1 with `pnpm nx run db:codegen`.

Proof hint: `libs/db/src/lib/extensions/tests/verify-provider-ordering-admin-S27.spec.ts`

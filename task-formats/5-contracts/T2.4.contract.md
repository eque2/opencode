# Contract T2.4 — Add the dry-run mode to the gateway

> **Goal.** Let a caller ask "who would serve this?" and get a truthful answer without a provider call or a charge.

## Requires

- T1.4 is trusted — Create the generic dry-run vocabulary

## Changes

- `libs/media/src/media-gateway.ts` — update: `GatewayRoutingContext` gains an optional dry-run field

## Ensures

What must be true when the work is done.

- **T2.4.c1** — `'succeed'` resolves routing, records attribution, returns a synthetic success naming the provider.
  - proof: the test tagged `[T2.4.c1]`
  - judge: runner + verifier
  - category: happy path; relates to S8
- **T2.4.c2** — `'fail'` returns the synthetic typed failure, attribution still recorded.
  - proof: the test tagged `[T2.4.c2]`
  - judge: runner + verifier
  - category: happy path; relates to S9
- **T2.4.c3** — no dry-run mode supplied → the call behaves exactly as before, including being charged.
  - proof: the test tagged `[T2.4.c3]`
  - judge: runner + verifier
  - category: empty / null; relates to S42
- **T2.4.c4** — a dry run on a pair with one candidate, and on a pair configured to serve nothing (the routing failure surfaces; the dry run does not mask it).
  - proof: the test tagged `[T2.4.c4]`
  - judge: runner + verifier
  - category: boundary
- **T2.4.c5** — no provider is contacted under either mode.
  - proof: the test tagged `[T2.4.c5]`
  - judge: runner + verifier
  - category: failure mode; relates to S10
- **T2.4.c6** — the wallet balance is unchanged and no charge row is created.
  - proof: the test tagged `[T2.4.c6]`
  - judge: runner + verifier
  - category: money; relates to S53
- **T2.4.c7** — the dry-run idempotency key cannot collide with a live call's, so a dry run can never satisfy or poison a real request's idempotency.
  - proof: the test tagged `[T2.4.c7]`
  - judge: runner + verifier
  - category: security boundary

## Preserves

- **T2.4.p1** — the estimate-drift / re-confirmation gate
  - proof: review of the parent's diff
  - judge: reviewer
- **T2.4.p2** — `deriveIdempotencyKey` — extended, not replaced
  - proof: the test tagged `[T2.4.c7]`
  - judge: runner + verifier
- **T2.4.p3** — `admitPinnedProviderId`
  - proof: review of the parent's diff
  - judge: reviewer

## Contributes to

- acceptance: S8, S9, S10, S42, S53 — see [acceptance.contract.md](./acceptance.contract.md)

## Not in this contract

- the short-circuit itself — this task supplies the mode and the money guarantee → T2.5

## Rejected proofs

A verdict that accepts one of these is void.

- c5: asserting the returned value only. Use a provider stub that fails the test if it is entered.
- c6: checking the response. Read the wallet balance and the charge rows before and after.
- c7: checking that a key exists. Derive both keys for the same request and assert they differ.

## Approach

Guidance for the builder. Not an obligation; nothing here is judged.

Extend the input of `deriveIdempotencyKey` so the mode is part of the key: a dry run must neither collide with nor poison a live call's idempotency key.

Proof hint: `libs/media/src/tests/verify-provider-ordering-admin-S8.spec.ts`

# Contract T2.5 — Move the dry-run short-circuit to the attempt boundary so attribution is shape-identical

> **Goal.** Make a dry run produce the *same* attribution record a live call produces — which is the entire reason a dry run can be used as proof.

## Requires

- T1.4 is trusted — Create the generic dry-run vocabulary
- T2.4 is trusted — Add the dry-run mode to the gateway

## Changes

- `libs/media/src/candidate-execution.ts` — update: the short-circuit sits after the candidate is chosen and before the provider adapter is entered, where the attempt record is still produced

## Ensures

What must be true when the work is done.

- **T2.5.c1** — the attempt record produced under dry run carries the same fields, in the same shape, as a live attempt record, differing only by the dry-run marker.
  - proof: the test tagged `[T2.5.c1]`
  - judge: runner + verifier
  - category: happy path; relates to S55
- **T2.5.c2** — the short-circuit happens after the candidate is chosen and before the provider adapter is entered — assert with a provider stub that fails the test if entered at all.
  - proof: the test tagged `[T2.5.c2]`
  - judge: runner + verifier
  - category: boundary; relates to S10
- **T2.5.c3** — `'fail'` produces an attempt record marked failed, and the failover machinery is *not* triggered by it (a synthetic failure is not evidence that a provider is unavailable).
  - proof: the test tagged `[T2.5.c3]`
  - judge: runner + verifier
  - category: failure mode
- **T2.5.c4** — `AllProvidersExhausted` and `IncompatibleRequestSchema` semantics are unchanged for live calls.
  - proof: the test tagged `[T2.5.c4]`
  - judge: runner + verifier
  - category: regression

## Preserves

What must still be true.

- **T2.5.p1** — `AllProvidersExhausted` and `IncompatibleRequestSchema` semantics for live calls
  - proof: the test tagged `[T2.5.c4]`
  - judge: runner + verifier
- **T2.5.p2** — no provider adapter is entered on a dry run
  - proof: the test tagged `[T2.5.c2]`
  - judge: runner + verifier

## Forbids

- **T2.5.f1** — Must not let a synthetic failure trigger failover — otherwise `dryRun: 'fail'` would silently exercise the whole chain and report the wrong provider
  - proof: the test tagged `[T2.5.c3]`
  - judge: runner + verifier

## Contributes to

- acceptance: S10, S55 — see [acceptance.contract.md](./acceptance.contract.md)
- gates: BUILD-4 — see [gates.md](./gates.md)

## Rejected proofs

A verdict that accepts one of these is void.

- c1: comparing a few chosen fields. Compare the dry-run and live attempt records field by field.
- c3: asserting the failure only. Assert that the failover machinery made no further attempt.

## Approach

Guidance for the builder. Not an obligation; nothing here is judged.

Placing the short-circuit here rather than higher in the gateway is what buys the shape-identity (POA-A3.b); the "no adapter entered" property is preserved and separately asserted.

Proof hint: `libs/media/src/tests/verify-provider-ordering-admin-S55.spec.ts`

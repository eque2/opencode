# Verify T2.3 — Update the router so a pair configured to serve nothing is not treated as unconfigured

## Cases

A case is proved by a passing test whose title starts with its tag, for example `[T2.3.c1]`.

- `T2.3.c1` · *happy path* — a configured pair routes to its first enabled candidate in stored order, reported as `'policy'`.
- `T2.3.c2` · *empty / null* — an absent pair routes by `orderedCandidatesFor`, reported as `'default-precedence'`. (→ S6, S44)
- `T2.3.c3` · *boundary* — a pair configured with every provider disabled fails with a typed error naming the pair, distinguishable from the absent case. (→ S7)
- `T2.3.c4` · *boundary* — a disabled provider is never a candidate, even when every enabled candidate has failed. (→ S3, S22)
- `T2.3.c5` · *invalid input* — an override naming a disabled provider is refused by the existing `OverrideNotACandidate`, not silently honoured.
- `T2.3.c6` · *regression* — candidate order is verbatim and never re-sorted; a policy for a pair remains strictly additive over default precedence for every pair that is merely absent.

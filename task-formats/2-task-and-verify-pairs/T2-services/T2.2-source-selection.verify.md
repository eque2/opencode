# Verify T2.2 — Wire source selection, polling and load semantics

Work: [T2.2-source-selection.task.md](./T2.2-source-selection.task.md)

## Cases

A case is proved by a passing test whose title starts with its tag, for example `[T2.2.c1]`.

- `T2.2.c1` · *happy path* — configuration selects the database source; the poller loads it on the existing interval.
- `T2.2.c2` · *boundary* — re-reading an unchanged configuration reports `unchanged` and does not advance the generation counter. (→ S40)
- `T2.2.c3` · *boundary* — a policy replacement landing mid-request does not change the decision that request already resolved; a request begun afterwards sees the replacement. (→ S39)
- `T2.2.c4` · *failure mode* — a malformed projection is refused and the readiness surface reports `serving-stale`. (→ S18)
- `T2.2.c5` · *failure mode* — the store is unreachable for several consecutive polls; the policy in force keeps serving throughout. (→ S21)
- `T2.2.c6` · *concurrency* — a poll that began before an Apply and completes after it does not reinstate the pre-Apply configuration — the swap refuses a document whose revision is older than the one in force. (→ S57, POA-R2)
- `T2.2.c7` · *invalid input* — a document refused by the catalogue-binding check leaves the previous policy serving and is reported. (→ S59)
- `T2.2.c8` · *backwards compatibility* — the GCS-configured deployment path is untouched. (→ S41)

## Weak proofs to reject

- c2: asserting only that the outcome says `unchanged`. Assert that the generation counter did not advance.
- c3: swapping the policy before the request starts. The replacement must land after the request has resolved its decision and before it completes.
- c6: running the poll and the Apply one after the other. The poll must begin before the Apply and complete after it, or the test cannot fail.

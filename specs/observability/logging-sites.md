# Logging capture sites

This catalogue lists every code site where opencode can capture a log or telemetry record. It is the input for the patterns in [`logging-patterns.md`](./logging-patterns.md) and for the Datadog sink in `packages/core/src/observability/datadog.ts`.

Coverage against the Datadog sink is in [`logging-gaps.md`](./logging-gaps.md).

The survey was made on branch `effect-v4-update` (Effect `4.0.0-rc.117`) on 2026-09-27. Line numbers drift. Search for the symbol name when a line does not match.

## How to read the tables

All paths are relative to `packages/`.

**Category.** Each site has a proposed log `category` annotation. The Datadog sink filters on this annotation with `OPENCODE_DATADOG_CATEGORIES`, so the taxonomy is the switchboard for what leaves the machine.

| Category prefix                                                                                     | Covers                                                                |
| --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `llm.request`, `llm.stream`, `llm.usage`, `llm.retry`, `llm.error`                                  | Provider calls, streaming, token use and cost, retries, mapped errors |
| `llm.prompt`, `llm.system`                                                                          | Final prompt and system-prompt assembly                               |
| `provider.*`, `auth.*`                                                                              | Model and provider resolution, credential and OAuth refresh           |
| `session.*`                                                                                         | Prompt admission, loop, status, compaction, revert, subagents         |
| `tool.call`, `tool.result`, `tool.error`, `tool.<name>`                                             | Tool execution envelope and individual tools                          |
| `permission.*`, `question.*`                                                                        | Permission and question requests and replies                          |
| `mcp.*`, `lsp.*`, `plugin.*`                                                                        | Integrations                                                          |
| `http.*`, `sse.*`                                                                                   | Server requests, auth, event streams                                  |
| `config.*`, `bus.*`, `storage.*`, `sync.*`, `share.*`, `workspace.*`, `git.*`, `process.*`, `cli.*` | Infrastructure                                                        |

**Existing.** `fn` is an `Effect.fn("Name")` span. `span` is `Effect.withSpan`. `log` is an `Effect.log*` call. `event` is a Bus or `EventV2` publish. `hook` is a plugin hook. `none` means the site is silent today.

**Sensitivity.** `S` is secrets (API keys, tokens, auth headers, env). `P` is prompt or completion content, which can hold personal data. `C` is shell command text. `F` is file contents or diffs. `U` is user free text (answers, feedback). `I` is identifiers and paths. `N` is not sensitive. Under the Eque2 data-loss-prevention rules, `S` must never leave the machine, and `P`, `C`, `F` and `U` must be omitted or hashed unless an operator opts in.

**Priority.** `1` is a high-value site with no capture today. `2` has partial capture. `3` is lower value or noisy.

## Two execution stacks

opencode runs two stacks side by side. Instrument both until V1 retires.

- **V1** is the live path in `packages/opencode`. The AI SDK dispatches tools, and `EventV2Bridge` republishes V1 bus events.
- **V2** is the durable path in `packages/core` (`SessionRunner`). Every state change is a durable `EventV2` event.

## Existing infrastructure

- **Loggers.** `core/src/observability.ts` builds one root logger set with `mergeWithExisting: false`, which replaces the default console logger that corrupts the TUI.
  - A logfmt file logger writes to `~/.local/share/opencode/log/opencode.log`.
  - A stderr logger runs when `OPENCODE_PRINT_LOGS=1`.
  - An OTLP logger runs when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.
  - A Datadog logger runs when `DD_API_KEY` is set.
- **Level.** `OPENCODE_LOG_LEVEL` (default `INFO`) sets `References.MinimumLogLevel`. The CLI flags `--log-level` and `--print-logs` write these env vars before the layer builds.
- **Traces.** `Otlp.tracingLayer` builds an OpenTelemetry Node SDK with an OTLP exporter. It also registers a global context manager, which the AI SDK needs. There are no metrics.
- **Mount points.** `Observability.layer` is provided in `opencode/src/effect/app-runtime.ts:58-111`, `server/routes/instance/httpapi/server.ts:311` ("must stay last"), `effect/run-service.ts:33` and `core/src/effect/runtime.ts:5`. `server/server.ts:124` builds with a fresh memo map, so it can build a second logger set. The standalone `server/src/routes.ts` has no observability layer.
- **Spans.** About 857 named `Effect.fn` sites exist. Only `Tool.execute` spans carry attributes.
- **Redaction.** `llm/src/route/executor.ts:41-202` redacts headers, URL parameters and body fields. The Datadog sink redacts secret-named keys and omits or hashes content keys.

## Gaps to close first

1. **Silent high-value sites.** Native LLM retries (`executor.ts:353`), OAuth refreshes (`integration.ts:399`, Codex, xAI, Snowflake), tool-call repair (`session/llm.ts:296`), V2 session idle (`run-coordinator.ts:59`), auto-allowed permissions, V2 compaction failure, retry give-up, and command-template shell runs.
2. **No HTTP access log and no 401 log.** All routers set `disableLogger: true`.
3. **Swallowed errors.** LSP spawn and initialise, LSP stderr, MCP `listTools`, MCP transport fallback, plugin `event` hook rejections, TUI worker crashes, and fatal CLI errors (stderr only).
4. **Existing logs that already carry content.** `question/index.ts:125` (answers), `permission/index.ts:74` (command patterns), `pty.ts` (cmd and args), `session/llm.ts:283` (raw provider error), `proxy.ts:114` (upstream body), `mcp/index.ts:474` (server data) and `POST /log` (client data). The Datadog sink handles these by key, but the file log still records them.
5. **Tracing noise and privacy.** Per-chunk `Effect.fn` spans in the protocol handlers. AI SDK telemetry records prompts and outputs by default, and it attaches the configured username.
6. **Cost.** The V2 runner records `cost: 0` at `core/src/session/runner/llm.ts:333`.

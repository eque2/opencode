   `scenarioJudge`). `workers.ts` exports no `scenarioJudge`, no code in `src/` defines it, and no test covers it.
   The builder's journal and commit messages do not mention it or record a deviation. `verifierPrompt` could serve a

   shows that configuration, and the spec names a separate worker. Actionable fix: either add `scenarioJudge` (one
   judge prompt for a scenario in the root checkout, owned by the scenario supervisor, claim without watch, cancel on
   interrupt) with a test, or record the deviation (verifierPrompt is the scenario judge) in the spec and add a test
   that runs verifierPrompt as a scenario judge in the root checkout with a scenario owner.

group kill from a leader kill (the group kill is pre-existing code and H13 passes); the `touch` test asserts only
`Exit.void`; `restore` of the root checkout under the checkout lock has no test (not a named test case).

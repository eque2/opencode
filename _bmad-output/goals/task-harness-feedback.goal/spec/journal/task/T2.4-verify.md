3. State Transitions, done stores nothing and returns — COVERED. A record after `done` succeeds and the store stays
   `["run.started","run.cancelled"]`.
4. Error Propagation, interrupt mid-record gives both or neither — GAP (vacuous test). `Effect.forkChild` schedules
   the child (`forkUnsafe`, `immediate = false`), and `Fiber.interrupt` runs before the child starts. An unstarted
   interruptible fiber exits at once in `interruptUnsafe` (`evaluate(failCause(...))`), and the later scheduled
   `evaluate` returns because `_exit` is set. So `record` never runs, and `expect(stored.some(...)).toBe(folded)`
   compares false with false. The test passes with or without `Effect.uninterruptible`; it never reaches the
   window between publish and send.
5. Happy Path, writer once per committed macrostep, final included, touch rewrites last snapshot, no write after

   writes nothing, and the touch rewrite is equal to the last snapshot (writer test 2). "Once per committed
   macrostep" is not asserted: the test only polls for three end states and counts no writes, so a writer that
   skipped or duplicated intermediate macrosteps would pass.
6. Resource Limits, `Queue.sliding(1)` burst gives at most one pending write; touch after the run scope closed

7. Timing, each write stamps `run.aliveAt` from the clock — COVERED, weak. `aliveAt` > 1e12 and a touch write has a

8. State Transitions, SV21 stub finalizer added first sees the writer stopped — COVERED. `seen` equals `[true]`

9. Concurrency, A records `done` while B waits on the permit; B stores nothing — COVERED, weak. Store equals
   `["run.started","run.cancelled"]` after a concurrent cancel and resume. Contention is not forced.
10. Error Propagation, publish fails gives no send and a caller failure; record after scope close stores nothing —
    COVERED. `Exit.isFailure`, actor log `[]`; the closed-scope recorder stores `[]` and does not fail.
11. Empty / Null, touch before first change never throws; a failed write is logged and the next macrostep writes —
    PARTIAL. Touch before the first change succeeds and the writer still writes; after a failed write
    (`.opencode` is a file) the next macrostep writes `building`. "Is logged" is not asserted, and the failed write is
    timing-dependent (a 50 ms sleep before the file is removed).
12. Timing, resume clock below last stored `at` — COVERED. TestClock 4 000, stored `at` 9 000, new fact `at` 9 000.
13. Error Propagation, SV26: after `error`, record stores nothing, logs, fails; the writer writes nothing more —
    PARTIAL. Store count unchanged and `Exit.isFailure` are asserted. "Logs the defect" and "the writer writes
    nothing more" have no assertion (no status file or writer-fiber check after the error).

## Verdict
REJECTED. Test case 4 is vacuous, test case 6 has no assertion for either claim, and test cases 5, 11 and 13 assert
only part of their claims. The implementation reads correct (`Effect.uninterruptible`, `Queue.sliding(1)`,
`Stream.takeWhile` on error); the tests do not prove it.

Suggested fixes for the builder (tests only):
- TC4: give `record` an events stub whose `publish` waits on a Deferred; start the record, wait until publish is
  entered, interrupt the caller, release the Deferred, then assert the fact is both stored and folded.
- TC6: count `TaskStatus.write` calls (or file writes) across a burst while the writer is blocked, and assert at
  most one write follows; add a `touch` after `Scope.close` of the run scope that returns void.
- TC5: count writes per recorded fact (one per committed macrostep, the final one included).
- TC13: after the error, assert the writer fiber is done (or that `status.json` does not change on a later touch),
  and capture the log for the defect line.
- TC11: capture the log for the failed write; make the failure deterministic.
- Optional: force contention in TC2/TC9 with a gated publish.

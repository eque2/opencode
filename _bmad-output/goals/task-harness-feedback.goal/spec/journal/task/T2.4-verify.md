## Verdict
REJECTED. Test case 4 is vacuous, test case 6 has no assertion for either claim, and test cases 5, 11 and 13 assert
only part of their claims. The implementation reads correct (`Effect.uninterruptible`, `Queue.sliding(1)`,
`Stream.takeWhile` on error); the tests do not prove it.

Suggested fixes for the builder (tests only):
- TC4: give `record` an events stub whose `publish` waits on a Deferred; start the record, wait until publish is
  entered, interrupt the caller, release the Deferred, then assert the fact is both stored and folded.
- TC6: count `TaskStatus.write` calls (or file writes) across a burst while the writer is blocked, and assert at
  most one write follows; add a `touch` after `Scope.close` of the run scope that returns void.
- TC5: count writes per recorded fact (one per committed macrostep, the final one included).
- TC13: after the error, assert the writer fiber is done (or that `status.json` does not change on a later touch),
  and capture the log for the defect line.
- TC11: capture the log for the failed write; make the failure deterministic.
- Optional: force contention in TC2/TC9 with a gated publish.

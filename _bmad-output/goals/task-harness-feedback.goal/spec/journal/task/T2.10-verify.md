## DECISIVE GAPS
- Error Propagation (failed touch is logged) — GAP. Test 12 ("logs a failed touch...") asserts only that 3 failed
  touches record no fact and the heartbeat is back in `beating`. It captures no log. In run.ts,
  `heartbeat.touching.invoke.onError: "beating"` has no log action. The comment says "logged by the actor's logger",
  but xstate-effect logs an actor error only when nothing handles it (`Actor.ts` reportError: no observers and no
  parent, or an observer without an error listener). An invoked child has a parent, and `onError` handles the error.
  A scratch probe against the same library build (handled `fromEffect` failure in a loop, captured Logger) gave
  7 failures and 0 log messages. SV5 also requires "a touch that fails is logged".
- Error Propagation (staleCheck fails 3 times: logs each failure) — GAP. Test 14 asserts 4 checks ran, the stored
  types are `["run.started"]`, and the status is `active`. It captures no log. `staleCadence.checking.invoke.onError:
  "waiting"` has no log action, so each failure is silent. The builder journal's "a failure is logged" is not backed
  by the code.
- Fix (for the builder): log each touch failure and each stale-check failure (an xstate log action on `onError`, or
  `Effect.tapCause(Effect.logWarning)` in the actor's Effect), and assert the log in tests 12 and 14 with a captured
  `Logger.layer`. Tests 17 and 18 already use that pattern.

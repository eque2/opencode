### The earlier gap: `repeated` (Security Boundaries, SV13; AD-10, AD-11)

Closed. New test "records task.repeated for a turn that repeated itself, before its task_ready and with no nudge":
the building turn sends `hook.ready` and then `hook.repeated` (reason "repetition: 3 identical bash calls in a row"),
then ends. The test expects the stored facts to be exactly `[task.repeated { task: T1.1, reason: <the hook's
reason> }]` (`toMatchObject` and `storedTypes` `toEqual`). So no `task.ready` and no `task.nudged`, and the reason
flows from the hook through `context.repeated` into the fact. A machine without the `repeated` row of `ended` goes to
`readying` (its commit fails on the fixture worktree, the retry starts a new turn that clears the hooks and ends idle)
and records a different fact, so the test fails. A machine without the `hook.repeated` handler fails the same way.
New test "records a spend cap that ended the turn before a repetition in the same turn": the turn sends
`hook.repeated`, and its assistant message carries `insufficient_quota`. The test expects exactly
`[task.needs_human "spend cap: insufficient_quota"]`. So the order spend cap, then repetition, then task_ready is now
pinned at both steps. The snapshot reads after the first test (`prompt` "attempt", `nudges` 0) are weak (both are
the initial values), but they are extras, not the proof.

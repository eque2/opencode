## The gap (test case 5)

A read-only probe (scratchpad, the same facts as the RM8a test) shows that the fold reaches status `done` at the
16th fact, `task.failed` (T1.2 needs_human + T1.1 failed block every other unit, so `active` is final). After that,
`scenario.proved`, `scenario.verified` and `run.ended { state: "done" }` each return the identical snapshot
through the done pass-through. Without the `run.ended` fact the fold is still `done` with run state `needs_human`.

So the assertions `status === "done"`, `view.run.state === "needs_human"` and `ended === true` hold whether or not
the machine can fold `run.ended`. The test never sends `run.ended` (or `scenario.verified`) to the machine's
transition. Also, `run.cancelled` is missing from the "every member" list and is never decoded (it folds only in
the RM6 test). The comment "Every member of the stored-fact schema is here, so each decodes and folds" is false.

A second probe shows the code is correct: on an active snapshot, `scenario.proved`, `scenario.verified` (S2 to
trusted) and `run.ended { state: "done" }` (status done, run state done) all fold.

## Fix for the builder

- Put the stored `run.ended { state: "done" }` (and the scenario facts) where the run is still `active`, and
  assert that this fact changes the snapshot (`not.toBe(previous)`) and that the stop gives its own run state.
- Add `run.cancelled` to the decoded set, or derive the expected type list from `FactSchema.members`.

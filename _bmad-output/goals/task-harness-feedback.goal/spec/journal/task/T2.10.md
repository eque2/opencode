# T2.10 — the run supervisor with its parallel timer regions

- RED: `packages/opencode/test/task/supervise-run.test.ts` (21 tests; failed on the missing module). GREEN:
  `packages/opencode/src/task/core/supervise/run.ts`.
- States: `starting` (record run.started or run.resumed with path and base; forwarded trusts kept) → `trusting` (the
  directory's trusts and the kept ones, each once, only for untrusted outside regions; external regions and tasks
  never) → `running` (parallel) → `closed`.
- `running.main`: the `watch` actor relays each run snapshot as `run.changed` (and the final snapshot when the actor's
  changes end, because they end without it). `dispatch` spawns a task supervisor per task tagged ready or active and a
  scenario supervisor per scenario in verifying (system ids `task:<runID>:<id>`, `scenario:<runID>:<id>`), stops one

  supervisor spawned now starts from its unit's newest entry with its tags, session, runStart and task clock. A
  forwarded `run.trust` records `outside.trusted` once. A unit supervisor that errors records its unit's failure fact
  with `harness error: <defect>`. When the run actor is done (or errors), `main` waits for the writer, frees the
  lease, logs a run actor defect, and closes.
- Regions: `heartbeat` (touch after 5 s, back on done or error), `wallClock` (run.ended failed after runWallClock),
  `staleCadence` (stale check after 1 s; obligation.stale, then spec.reloaded to the unit supervisors; a failure is
  logged and the cadence goes on), `scenarios` (one batch proof of the ready scenarios at a time; three failures fail
  the batch). Each region stops on `run.ended`. No cross-region target, no re-entering timer row.

  first fact, run.cancelled; then cancelDeadline; then removeRun).

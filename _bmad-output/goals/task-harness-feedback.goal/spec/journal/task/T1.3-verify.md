### Verdict

rejected — the tests pass, and the code holds the rules, but four non-N/A test cases are not fully covered by an
assertion:

1. Boundary RM29: add negative controls through `TaskMachine.fromConfig` for the ready row removed, a wrong cause, a
   cancelled row removed, the S13 parked row removed, a non-final state with no rows ("has no way out"), and a
   blocked row that reads two states. Assert each message.
2. Invalid Input RM28: add a copy with a guard on an unknown id and assert `fromConfig` throws "a guard names the
   unknown state id"; or scan every `stateIn` id of the real config against the set of node ids.
3. State Transitions (building dependant): finish the run (or use a plan where it settles) and assert the outcome
   `budget_exhausted`.
4. State Transitions RM15: assert the guard of the task ready → waiting row, or fold a task from ready back to
   waiting when a dependency is reopened.

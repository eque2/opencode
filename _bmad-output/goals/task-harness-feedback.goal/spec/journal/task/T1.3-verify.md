### Observation (not blocking)

The scan evaluates all-trusted, each single dependency in each blocking state with the others trusted, and each
untrusted outside need; it does not enumerate mixed combinations. Probe (a) shows that a row which reads two dead
states and targets `ready`, put before the blocked rows, passes the scan. This does not let a unit get stuck: every
(dependency, blocking state) pair must have a single-state blocked row (the scan checks it), so some row is enabled
in every combination with a dead dependency. The cause in a mixed combination depends on the fixed row order, which
the generator gives from one function and RM15 pins for T1.5 and T1 waiting. That matches the owner's "fixed order +
check". A follow-up could add an order rule to the scan (no row before a blocked row reads more than one state) so
that the scan alone proves every combination. The scan also never names a `blocked` dependency in a negative
control; probe (b) shows the rule holds.

## Gaps

1. **Concurrency (EFX-31) is untested.** No assertion shows that the `execute` callback runs the hook Effect with the
   context that `createTaskHarnessTools` captured. `HarnessHooks` members are `Effect<_, never, never>`, and no test
   provides a service, `Context.Reference`, log annotation, logger or span around `createTaskHarnessTools` that the
   hook Effect then reads. Replacing `Effect.runPromiseWith(yield* Effect.context())` with `Effect.runPromise` passes
   every test, and no lint rule bans the bare run. Actionable fix: create the tools under a provided
   `Context.Reference` (or `Effect.annotateLogs` with a test logger), pass a stub `HarnessHooks` whose `send` reads
   it, and assert the captured value (not the default) reaches `send`.
2. **Boundary: the snapshot read is weakly discriminated.** The owner stand-in's `limit` is always 3, the default, so a
   `limitOf` that returns a constant 3 for any live owner passes. "No send before the read" is true by code inspection
   only; no test records the call order. Actionable fix: an owner whose context `limit` is 2, asserting `limitOf` =
   Some(2) and a stop after two identical calls (and none after one); a spy `HarnessHooks` that records the order
   `ownerOf`, `limitOf`, then `send`.

## Verdict

Rejected: two non-N/A test cases (Concurrency, and part of Boundary) lack a discriminating assertion. The code itself
looks correct; the defect is in the proof, not the routing.
